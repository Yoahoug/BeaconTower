# 01 · 需求分析

## 1. 项目定位

BeaconTower（信标塔）是一个**自托管**的服务器性能监控面板：

- 面板本身是一个 Docker 容器，部署在某台"中枢服务器"上；
- 面板通过 **SSH** 主动连接各台被监控服务器拉取指标，**被监控机不安装任何 Agent**；
- 对外提供公开的亮色卡片式状态页；管理功能在独立的管理后台中。

## 2. 核心功能需求

### 2.1 指标采集（SSH 无 Agent）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| C1 | SSH 连接被监控机 | 支持密码 / 私钥两种认证，支持非标准端口 |
| C2 | 实时指标 | CPU 使用率、内存/交换分区、磁盘占用、网卡实时速率、TCP/UDP 连接数、负载均值、进程数、运行时长；温度/GPU 为可选扩展（仅部分硬件支持，二期） |
| C3 | 系统画像（"服务器形象"） | 添加节点时自动回读：主机名、发行版与版本、内核、架构、CPU 型号与核数、内存/磁盘总量、虚拟化类型；此后每日刷新一次 |
| C4 | 采集周期 | 默认 10s，可配置（建议下限 5s）；采集失败指数退避并标记离线 |
| C5 | 一键测试连接 | 管理后台保存前先试连，回读画像预览 |
| C6 | **公网 IP 地理定位** | 采集会话内获取节点公网出口 IP，解析出国家/地区（城市可选）并**自动填充地区展示文案**，管理员无需手动输入"香港/东京"这类地区；面板宿主机直接读自身出网 IP；结果缓存，管理员可手动覆盖（IP 本身不公开、不展示） |

### 2.2 公开状态页（访客可见）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| P1 | 亮色卡片式总览 | 每台服务器一张卡片：状态、系统、CPU/内存/磁盘进度条、CPU 迷你走势、实时网速、在线时长 |
| P2 | 全网汇总条 | 总节点数、在线数、全网上/下行速率 |
| P3 | 节点详情页（二期） | 单节点历史曲线（1h / 24h / 7d / 30d） |
| P4 | 实时刷新 | SSE 推送，断线自动重连 |
| P5 | **敏感信息零暴露** | 公开 API/页面不出现 IP、主机名、SSH 端口、备注等；仅展示显示名、地区（IP 推导的地理文案，不含 IP 本身）、标签与指标 |
| P6 | 可选展示控制 | 管理员可设置某节点"隐藏"（不公开）、可控制卡片上出现哪些字段 |

### 2.3 管理后台（仅管理员）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| A1 | **首次访问初始化** | 数据库中无管理员时，`/admin` 显示初始化向导（设置用户名 + 强密码）；完成后该入口永久关闭 |
| A2 | 登录 / 登出 | 会话 Cookie；连续失败限速 |
| A3 | 节点 CRUD | 添加/编辑/删除/排序/隐藏，SSH 凭据（密码或私钥）加密入库 |
| A4 | 采集状态监控 | 每个节点的最近采集时间、失败原因（仅管理员可见） |
| A5 | 设置 | 采集间隔、数据保留时长、站点标题等 |
| A6 | 审计日志 | 记录登录、节点变更等管理操作 |

### 2.4 安全与隐私（横切）

| 编号 | 需求 |
| --- | --- |
| S1 | SSH 凭据（密码/私钥）以 AES-256-GCM 加密存储，密钥来自环境变量或首次启动生成 |
| S2 | 管理员密码 Argon2id 哈希存储 |
| S3 | 会话 Cookie：HttpOnly + SameSite=Strict，HTTPS 下自动 Secure；管理接口叠加 CSRF 防护 |
| S4 | 登录与初始化接口限速防爆破 |
| S5 | 安全响应头：CSP、X-Frame-Options、Referrer-Policy 等 |
| S6 | 公开数据白名单序列化（见 04 文档），从接口层面杜绝泄露 |
| S7 | 审计日志中的来源 IP 仅以哈希形式存储，仅管理员可见 |

## 3. 非功能需求

- **单二进制 + 单容器**：前端 `go:embed` 进后端，Docker 镜像一个进程搞定；
- **低资源**：中枢面板 idle 内存 < 100MB；被监控机除 SSH 服务外零额外开销；
- **规模**：目标 3 ~ 100 台节点规模（SSH 轮询模型的决定性约束，见 02 文档）；
- **易备份**：数据目录内一个 SQLite 文件 + 密钥文件，复制即备份；
- **中文优先**：界面与文档以中文为主。

## 4. 明确不做的事（v1 范围控制）

- ❌ 不做告警通知渠道（Telegram/邮件等）—— 二期再议；
- ❌ 不做计划任务、DDNS、NAT 穿透等 Nezha 式扩展功能；
- ❌ 不做多人/多租户，仅单管理员；
- ❌ 不做暗色主题（亮色为唯一主题，预留 CSS 变量可扩展）；
- ❌ 不在公开页展示能定位到"具体某台机器"的信息：IP、SSH 地址/端口永不公开；地理信息由 IP 自动推导但仅到国家/地区级（城市级默认关闭，管理员可开），IP 本身不出现在任何公开接口。
