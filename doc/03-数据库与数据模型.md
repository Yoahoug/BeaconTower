# 03 · 数据库与数据模型

## 1. 选型结论

**SQLite 单文件库**（`data/beacontower.db`），驱动用 `modernc.org/sqlite`（纯 Go，无 CGO）。开启 WAL 模式 + `busy_timeout`。完整论证见 02 文档第 3 节。

## 2. 表结构（v1）

```sql
-- 管理员（仅一条记录；首次访问 /admin 时通过初始化向导创建）
CREATE TABLE admin (
  id            INTEGER PRIMARY KEY CHECK (id = 1),   -- 恒为 1，存在即"已初始化"
  username      TEXT    NOT NULL,
  password_hash TEXT    NOT NULL,                     -- argon2id 编码串
  totp_secret   BLOB,                                  -- 预留：AES-GCM 加密存储（二期）
  created_at    INTEGER NOT NULL,                      -- unix 秒
  last_login_at INTEGER
);

-- 服务器节点
CREATE TABLE server (
  id           INTEGER PRIMARY KEY,
  name         TEXT    NOT NULL,          -- 显示名（公开），管理员自定义
  region       TEXT    DEFAULT '',        -- 地区展示文案，如 "香港"（region_source=auto 时由后端按公网 IP 解析写入）
  region_source TEXT   DEFAULT 'manual',  -- auto = IP 自动定位 / manual = 管理员覆盖（覆盖后不再自动更新）
  tags         TEXT    DEFAULT '[]',      -- JSON 数组
  note_public  TEXT    DEFAULT '',        -- 公开备注（访客可见；借鉴 Nezha 公私备注分离，官方约定不放入敏感内容）
  note_private TEXT    DEFAULT '',        -- 私有备注（仅管理端：用途、账单、到期日等）
  sort_order   INTEGER DEFAULT 0,
  hidden       INTEGER DEFAULT 0,         -- 1 = 不在公开页展示
  enabled      INTEGER DEFAULT 1,         -- 0 = 暂停采集
  created_at   INTEGER NOT NULL
);

-- SSH 连接信息（独立表，敏感字段加密；host/port 仅管理端可见，公开 API 永不返回）
CREATE TABLE server_credential (
  server_id        INTEGER PRIMARY KEY REFERENCES server(id) ON DELETE CASCADE,
  host             TEXT NOT NULL,          -- IP 或域名
  port             INTEGER NOT NULL DEFAULT 22,
  username         TEXT NOT NULL,
  auth_type        TEXT NOT NULL CHECK (auth_type IN ('password','key')),
  password_enc     BLOB,                   -- AES-256-GCM 密文（auth_type=password）
  private_key_enc  BLOB,                   -- AES-256-GCM 密文（auth_type=key）
  passphrase_enc   BLOB,                   -- 私钥口令密文（可空）
  host_key_fp      TEXT,                   -- 首次连接记录的 host key 指纹 (SHA256:...)
  last_error       TEXT,                   -- 最近一次采集失败原因（仅管理端）
  last_success_at  INTEGER
);

-- 系统画像（"服务器形象"）：首次连接回读，每日刷新
CREATE TABLE server_profile (
  server_id   INTEGER PRIMARY KEY REFERENCES server(id) ON DELETE CASCADE,
  hostname    TEXT,                        -- 仅管理端可见
  os_name     TEXT,                        -- 如 Ubuntu
  os_version  TEXT,                        -- 如 24.04
  kernel      TEXT,
  arch        TEXT,                        -- x86_64 / aarch64
  cpu_model   TEXT,
  cpu_cores   INTEGER,
  mem_total   INTEGER,                     -- 字节
  swap_total  INTEGER,
  disk_total  INTEGER,                     -- 根分区所在盘容量，字节
  disks_json  TEXT,                        -- 全部挂载点明细（仅管理端）
  virt        TEXT,                        -- KVM / 物理机 / lxc...
  public_ip   TEXT,                        -- 公网出口 IP（SSH 会话内回读或本机直读；仅管理端可见，公开 API 永不返回）
  geo_country TEXT,                        -- 国家/地区码，如 HK、JP（GeoIP 解析结果）
  geo_city    TEXT,                        -- 城市（公开默认不展示，站点级开关）
  geo_at      INTEGER,                     -- geo 最近解析时间（unix 秒；解析失败保留旧值）
  collected_at INTEGER
);

-- 实时快照缓存（每节点最新一条，热数据；重启后由此恢复前端展示）
CREATE TABLE latest_metric (
  server_id   INTEGER PRIMARY KEY REFERENCES server(id) ON DELETE CASCADE,
  ts          INTEGER NOT NULL,
  status      TEXT NOT NULL DEFAULT 'online',  -- online / offline
  cpu_pct     REAL,
  mem_used    INTEGER, mem_total INTEGER,
  swap_used   INTEGER, swap_total INTEGER,
  disk_used   INTEGER, disk_total INTEGER,
  net_in_bps  REAL, net_out_bps REAL,
  net_in_total INTEGER, net_out_total INTEGER,  -- 累计流量（字节）
  tcp_conns   INTEGER, udp_conns INTEGER,
  load1 REAL, load5 REAL, load15 REAL,
  uptime_s    INTEGER,
  processes   INTEGER
);

-- 原始采样：仅保留短窗口（默认 24h）
CREATE TABLE metric_sample (
  id       INTEGER PRIMARY KEY,
  server_id INTEGER NOT NULL REFERENCES server(id) ON DELETE CASCADE,
  ts       INTEGER NOT NULL,
  cpu_pct  REAL, mem_used INTEGER, swap_used INTEGER,
  disk_used INTEGER, net_in_bps REAL, net_out_bps REAL,
  tcp_conns INTEGER, udp_conns INTEGER,
  load1 REAL, load5 REAL, load15 REAL, uptime_s INTEGER, processes INTEGER
);
CREATE INDEX idx_sample_srv_ts ON metric_sample(server_id, ts);

-- 小时聚合：保留 30 天（长窗口曲线查询用，写入量降为 1/360）
CREATE TABLE metric_hourly (
  server_id INTEGER NOT NULL,
  hour_ts   INTEGER NOT NULL,            -- 整点 unix 秒
  cpu_avg REAL, cpu_max REAL,
  mem_avg INTEGER, mem_max INTEGER,
  net_in_avg REAL, net_out_avg REAL,
  net_in_total INTEGER, net_out_total INTEGER,   -- 该小时累计流量
  PRIMARY KEY (server_id, hour_ts)
);
```

> 建表 SQL 由程序启动时自动执行（含 `PRAGMA journal_mode=WAL`），采用简单迁移表 `schema_migration(version)` 记录版本，不做重型迁移框架。

## 3. 数据保留与聚合策略（可配置）

| 数据 | 保留 | 说明 |
| --- | --- | --- |
| 原始采样 `metric_sample` | 24 小时（默认） | 后台任务每 10 分钟清理过期行 |
| 小时聚合 `metric_hourly` | 30 天（默认） | 每小时整点 +5min 由后台任务从原始数据聚合写入 |
| 累计流量 | 跟随节点 | `/proc/net/dev` 计数器在节点重启后归零，检测到回退即重置基线 |
| 穿透用量快照 `frp_usage` | 30 天 | 每轮同步写一条（同分钟内只保留最后一条），10 分钟清理任务回收 |

写入量估算（默认 10s 间隔）：100 节点 ≈ 8.6k 行/小时原始数据，24h 约 20 万行，完全在 SQLite 舒适区内。

## 3.1 内网穿透表（migration v10，doc/13）

```sql
-- 平台账号：凭据加密 + 最新账号画像（每次同步覆盖）
CREATE TABLE frp_platform (
  id INTEGER PRIMARY KEY,
  kind TEXT NOT NULL CHECK (kind IN ('natfrp','chmlfrp')),
  name TEXT NOT NULL,
  token_enc BLOB,              -- Sakura 访问密钥 / ChmlFrp access_token
  refresh_enc BLOB,            -- 仅 ChmlFrp（一次性，刷新即轮换）
  token_expire_at INTEGER DEFAULT 0,
  uid TEXT, username TEXT, group_name TEXT, speed_limit TEXT, realname TEXT,
  tunnel_used INTEGER, tunnel_quota INTEGER, conns INTEGER,
  traffic_day_used INTEGER, traffic_remain INTEGER, traffic_up INTEGER, traffic_down INTEGER,
  status TEXT NOT NULL DEFAULT 'unbound',   -- unbound(需重新授权) / ok / error
  last_error TEXT, last_sync_at INTEGER, profile_json TEXT DEFAULT '{}',
  created_at INTEGER NOT NULL, updated_at INTEGER
);
CREATE UNIQUE INDEX idx_frp_platform_kind_name ON frp_platform(kind, name);

-- 隧道镜像：(platform_id, remote_id) 唯一，同步时 upsert + 删除平台侧已消失的行
CREATE TABLE frp_tunnel (
  id INTEGER PRIMARY KEY,
  platform_id INTEGER NOT NULL REFERENCES frp_platform(id) ON DELETE CASCADE,
  remote_id TEXT NOT NULL,     -- 平台侧隧道 ID（两平台都是数字，统一按字符串存）
  name TEXT, proto TEXT, node_id TEXT, node_name TEXT,
  local_ip TEXT, local_port INTEGER, remote TEXT,   -- remote：tcp/udp 是端口，http(s) 是域名
  online INTEGER, status TEXT, status_reason TEXT,
  conns INTEGER, today_up INTEGER, today_down INTEGER, uptime INTEGER, client_ver TEXT,
  extra TEXT, lock_edit INTEGER, lock_delete INTEGER, lock_migrate INTEGER, synced_at INTEGER
);

-- 节点镜像（整表替换语义）
CREATE TABLE frp_node (
  id INTEGER PRIMARY KEY,
  platform_id INTEGER NOT NULL REFERENCES frp_platform(id) ON DELETE CASCADE,
  remote_id TEXT NOT NULL, name TEXT, host TEXT, area TEXT, group_name TEXT,
  caps TEXT DEFAULT '[]',      -- 能力标签并集：http/https/web/udp/create/mainland/vip...
  online INTEGER, load REAL, uptime INTEGER, description TEXT, synced_at INTEGER
);

-- 用量快照：平台侧历史接口粒度不一（ChmlFrp 只有 7 天），面板自留一份画统一趋势
CREATE TABLE frp_usage (
  id INTEGER PRIMARY KEY,
  platform_id INTEGER NOT NULL REFERENCES frp_platform(id) ON DELETE CASCADE,
  ts INTEGER NOT NULL,
  traffic_day_used INTEGER, traffic_remain INTEGER, traffic_up INTEGER, traffic_down INTEGER,
  conns INTEGER, tunnel_online INTEGER, tunnel_total INTEGER
);
```

> `token_enc` / `refresh_enc` 为 AES-256-GCM 密文（与 SSH 凭据同一主密钥），
> 模型字段标 `json:"-"`，接口只下发 `has_token`。
> 两平台鉴权模型不同：Sakura 密钥长期有效无需刷新；ChmlFrp 的 access_token 仅 600 秒，
> 续期与落库的时序要求见 doc/13 §5。

## 4. 其他数据

| 项 | 存放 | 说明 |
| --- | --- | --- |
| 加密主密钥 | 环境变量 `BEACON_MASTER_KEY`（推荐）；未提供则首次启动生成 `data/master.key`（0600） | 用于 SSH 凭据字段加密，见 05 文档 |
| 会话 | SQLite 表 `session(token_hash, expires_at)` | 存 token 哈希，便于吊销 |
| 审计日志 | SQLite 表 `audit_log(ts, actor, action, target, detail, source_ip_hash)` | |
| 站点设置 | SQLite 表 `setting(key, value)` | 站点标题、采集间隔、保留天数等 |

## 5. 备份与恢复

- 备份：`sqlite3 data/beacontower.db ".backup backup.db"`（或直接停容器后复制 `data/` 整目录，含主密钥文件）；
- 恢复：把备份文件放回 `data/` 重启容器即可；
- 注意：**`data/master.key` 与数据库必须一起备份**，否则加密凭据无法解密（这是刻意的：单拿走数据库文件拿不到 SSH 密码/私钥）。
