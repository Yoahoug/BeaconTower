# 12 · WG 组网模块设计（一键 WireGuard 组网 + 主备 hub 轮换）

> 管理员模块：利用节点管理中已录入的 SSH 凭据，实现 WireGuard 星型组网的一键搭建、
> 现网导入纳管、设备凭证（二维码）分发、流量额度管家与 **A/B 双 hub 一键切换**。
> 设计前提（2026-09 现网实测）：单张 10.66.66.0/24 星型网，hub 虚拟 IP `10.66.66.2`
> 浮动于两台阿里云 VPS 之间（wg1 :51820 现役 / wg2 :51830 备胎），ops 为家庭 NAT
> 后的 spoke（主动拨出 + keepalive 25s），Mac/Win/iPhone 为用户设备 peer。

## 1. 背景与核心洞察

现网的 A/B 手工流程（bash_history 考古结论）：

- 两台云服务器配置**对等**（同子网、同 hub 虚拟 IP、同成员清单），各自持有独立密钥对；
- 某台**公网流量额度**快用完时，把「hub 身份」切到另一台：新 hub 全量重配 peer，
  spoke 与使用端设备改拨新 hub 的公网端点；
- **使用端只需切换一个凭证**（设备私钥不变，仅 [Peer] 的 PublicKey/Endpoint 不同）。

本模块把这个手工流程产品化：

| 手工动作 | 模块化后 |
| --- | --- |
| 逐台 `wg genkey` / 手写 conf / 手动 ufw | 向导自动：密钥面板生成、conf 渲染推送、防火墙自动放行 |
| hub 切换时逐台改 [Peer] 段 | 金丝雀两阶段一键切换（失败自动回滚） |
| 设备凭证手工生成 + qrencode 截图 | 面板生成密钥、conf + 前端二维码（每 hub 一份 A/B 凭证） |
| 流量额度人工估算 | 巡检按日累计 hub WG 转发流量，月度汇总 + 阈值进度条 |
| 配置漂移无人知晓（wg2 同 IP 遗留、残网） | 导入纳管 + 巡检公钥漂移/失联告警 |

## 2. 范围与边界

| 项 | v1 范围 |
| --- | --- |
| 拓扑 | 单网 + 主备 hub（hub 虚拟 IP 浮动）；不做全互联、不做 hub 迁移向导 |
| 系统 | Linux 内核态 WG：Ubuntu/Debian（apt）、RHEL 系（dnf/yum，EL7 走 EPEL） |
| 成员 | `server`（SSH 管理）与 `device`（面板发凭证，Mac/iPhone/Win） |
| 本机节点 | v1 不支持（面板容器无 NET_ADMIN）；引擎明确报错拒绝 |
| 采集地址 | 组网不改变现有监控采集链路（保持原 SSH 地址） |
| 密钥 | curve25519 面板侧生成（x/crypto），AES-256-GCM 加密入库，永不回显 |

## 3. 后端架构

```
internal/sshx      通用 SSH 执行器（从 collector 抽取）：Dial/Run/PushFile/AppendFile、
                   TOFU 指纹、错误中文分类、stdin→sh -s 免转义、输出 256KB 上限
internal/wg        core.go    密钥生成 / wg-quick conf 渲染解析 / wg dump 解析 / IP 分配
                   preflight.go  预检判定（纯函数：root/包管理器/端口/既有接口/环境告警）
                   engine.go  探测脚本、安装、EnsureForward/UFW、conf 写入/备份、
                              BringUp/BringDown、HubAddPeer（wg set + conf 追加）、
                              SyncConf（不断连重载）、VerifySpoke（ping+handshake 兜底）
                   task.go    Runner：凭据解密、任务编排（hub 串行→spokes 并行）、
                              RemovePeer（本侧下线+hub conf 重写+syncconf）
                   import.go  现网导入（读 hub dump+conf 建网收编、候选匹配升级、备援纳管）
                   switch.go  金丝雀切换（校正→金丝雀验证/回滚→全网翻转→置现役）
                   patrol.go  5min 巡检（判活/流量差值/公钥漂移）
internal/assets    资产中转：镜像变体生成、Range 并发测速、sha256 校验下载缓存
internal/handler   wg.go      /api/v1/admin/wg/*（envelope/CSRF/audit 同既有规范）
internal/store     wg.go      wg_* 表访问层（migration v7/v8）
```

### 3.1 关键运维细节（对齐现网习惯与教训）

- **改配置先备份**：`cp wgX.conf wgX.conf.bak.$(date +%Y%m%d%H%M%S)`（现网手工习惯）；
- **PostUp 幂等**：`iptables -C ... || iptables -A ...`（现网重启会重复叠加规则的教训）；
- **hub 加 peer 不断连**：`wg set` 热生效 + conf 追加（SaveConfig=false）；
- **hub 成员变更重写 conf 后用 `wg syncconf`** 而非重启接口（存量隧道零中断）；
- **PSK 经临时文件传给 `wg set`**（不出现在 ps/命令历史）；
- **spoke 切换优先就地改写原 conf 的 [Peer] 段**（保留节点 PostUp/MTU/DNS 个性化，
  如 ops 的 mihomo TUN 共存配置），仅无 conf 时才全量渲染；
- **FORWARD 默认 DROP** 的机器：hub conf 自带 PostUp 放行 wg0 进出（修复 wg2 手工规则
  不持久的问题）；hub 侧自动持久化 `net.ipv4.ip_forward=1`（/etc/sysctl.d/99-bt-wg-mesh.conf）。

## 4. 数据模型（migration v7/v8）

| 表 | 说明 |
| --- | --- |
| `wg_network` | 单网（id=1）：subnet、hub_ip（浮动虚拟 IP）、iface、keepalive、mtu、active_hub_server_id |
| `wg_hub` | hub 槽位（server_id PK）：listen_port、公私钥（加密）、endpoint、status、quota_gb、rx_cum/tx_cum（流量差值基线） |
| `wg_peer` | 成员：kind(server/device)、server_id(设备为 NULL)、wg_ip（UNIQUE）、公钥、私钥/PSK（加密，导入成员可为空）、status、handshake、rx/tx |
| `wg_task` / `wg_task_step` | 任务与步骤（apply/import/switch_hub），前端 2s 轮询 |
| `wg_hub_traffic` | hub 按日 WG 转发流量（巡检累计计数器差值累加） |
| `wg_asset` | 资产中转条目：多源 URL、sha256、面板缓存路径 |

**IP 分配**：Allocator 从子网内取最小空闲主机位（跳过网络/广播地址），DB 层
`UNIQUE(wg_ip)` 兜底防并发冲突；hub 虚拟 IP 与既有成员 IP 全部计入占用。

## 5. API（/api/v1/admin/wg/*，RequireAuth + CSRF + audit）

| 方法/路径 | 说明 |
| --- | --- |
| GET `/overview` | 总览：网络、hub 槽位（月流量/额度）、成员、服务器清单、任务占用 |
| POST `/plan` | dry-run：分配 IP + 并发 SSH 预检（issues 分 error/warn），不落库 |
| POST `/apply` | 执行组网（建网/hub 槽位/成员 → 任务后台执行）；hub 非现役时按备胎校正 |
| POST `/import` | 导入现网：读现役 hub 实况建网收编成员，候选 SSH 匹配升级，备援建 warm standby |
| POST `/switch-hub` | 金丝雀切换（见 §7） |
| POST `/patrol` | 手动巡检 |
| GET `/tasks/:id` | 任务详情（步骤状态+日志） |
| POST `/devices` | 添加设备成员（面板生成密钥 + 热加入现役 hub） |
| GET `/peers/:id/conf?hub=` | 导出成员凭证（A/B hub 各一份；导入成员不可导出） |
| POST `/peers/:id/verify` · DELETE `/peers/:id` | 手动验证 / 移出网络（hub syncconf 不断连） |
| GET/POST/DELETE `/assets`、`/assets/:id/probe`、`/assets/:id/fetch`、`/assets/:id/push` | 资产中转（§8） |

错误码：2010 预检/配置不通过、2011 执行失败、2012 IP 冲突（1004 沿用为任务冲突）。

## 6. 导入流程（对现网只读）

1. SSH 现役 hub → `wg show all dump`（运行态：公钥/端口/peer 握手/流量）+ conf
   （私钥/PSK/注释/MTU）→ 建网（subnet 取自 hub Address）→ hub 槽位收编私钥；
2. 未匹配的 peer 先落为 `device`（名称取 conf 注释，如 `# Win PC`）；
3. 逐个 SSH 候选服务器读其 conf → 由私钥推导公钥匹配 → 升级为 `server` 成员并收编其私钥
   （此后可被面板管理/切换）；
4. 备援 hub 读 conf 建槽位（与现役同钥会报错——A/B 依赖独立身份）。

导入全程只读，不改动任何节点配置；重复导入按公钥幂等更新。

## 7. hub 一键切换（金丝雀两阶段）

```
① 校正备援 hub     —— 全量重写 conf（DB 全部成员 + PSK）→ BringUp（闲置接口，零影响）
② 金丝雀 spoke     —— 就地改写 [Peer]（新 hub 公钥/端点/PSK）→ 重启接口 → ping hub_ip 验证
    失败 → 自动写回原 conf → 重启 → 回滚到原现役，任务 failed
③ 其余 SSH 成员   —— 并行翻转（金丝雀通过才执行）
④ 置换 active_hub —— 旧 hub 保留全量配置继续做备胎（warm standby）
                    结果摘要提示「N 台设备请切换凭证（A/B 重新扫码）」
```

关键约束：**同一时刻 spoke 只拨一个 hub**（[Peer] 单端点），切换过渡期未换凭证的
设备经由旧 hub 的路径会失联——这与现手工 A/B 流程的语义一致，由步骤 ④ 的凭证提示收尾。

## 8. 资产中转（兼顾国内外）

- 登记资产：name（节点上的可执行名）、version、sha256、多源 URL（官方直链 /
  镜像 / **自有仓库 release 直链**，作为最终兜底）；
- 测速：GitHub 链接自动生成加速镜像候选（ghfast.top / gh-proxy.com / ghproxy.net 等），
  Range GET 前 1KB 并发探测首字节延迟，可用优先 + 延迟升序；
- 下载：按序尝试，sha256 校验（登记了才校验），缓存 `data/assets/<name>-<version>`；
- 分发：经 SSH stdin 推送到节点 `/usr/local/bin/<name>`（0755）——节点零外网依赖；
- 单文件上限 512MB（下载）/ 32MB（SSH 推送）。

## 9. 巡检（5min ticker）

- 逐 hub 建连读 dump（hub 侧视角覆盖全网成员，每轮仅 N_hubs 次 SSH）；
- 成员判活：handshake ≤3min 在线（keepalive 25s 语义），更新 rx/tx；
- hub 当日流量：dump 累计计数器与 `wg_hub.rx_cum/tx_cum` 差值累加入
  `wg_hub_traffic`（负值=接口重启，重置基线不累加）；
- 异常检测：接口未运行 / 连接失败 / **接口公钥与面板记录不符**（配置被外部改动的信号）；
- 前端额度进度条：月累计 vs `quota_gb`，80% 标黄、100% 标红提示切换。

## 10. 前端（/admin/mesh，懒加载 chunk）

- 网络信息条（subnet / hub 虚拟 IP / 现役 hub / keepalive/MTU）；
- hub 额度卡：主备标记、endpoint、月流量进度条、切换按钮；
- 拓扑图：ECharts graph（力导向），节点按状态着色，箭头指向成员；
- 成员表：类型 / WG IP / 状态 / 握手 / 流量 / 操作（验证·凭证QR·移出）；
- 三步向导：选中心+勾成员（→子网/hub_ip 仅首次）→ SSH 预检结果 → 确认执行 → 任务进度；
- 导入弹窗 / 切换弹窗（金丝雀说明）/ 设备凭证弹窗（A/B 切换 + conf 文本 + 二维码 + 下载）；
- 资产中转弹窗（登记/测速/下载/推送）；任务进度 2s 轮询 wg_task/step。

## 11. 安全

- WG 私钥/PSK 与 SSH 凭据同等级加密（AES-256-GCM，主密钥同源），响应永不回显；
- conf 导出仅限 managed 成员且每次写审计（wg_peer_conf_export）；
- 所有远程命令为面板拼装（接口名/路径白名单净化），数据通道走 stdin（无引号注入面）；
- host key 沿用 TOFU/严格模式与既有 `strict_host_key` 设置。

## 13. 真机 E2E 实测记录（2026-09-28，现网三机）

流程：ops 起临时面板（18099）→ 导入现网（wg1 现役/wg2 备援/ops 匹配纳管，任务 done）→
wg2 备胎校正（apply hub=wg2，conf 全量重写 + PostUp + 备份）→ 金丝雀切换 wg1→wg2
（canary=ops，任务「成功 2」+ 设备凭证提醒文案）→ ops 本地看门狗切回 wg1（任务「成功 2」）→
三机快照比对全部通过（wg1 四 peer 各 /32、Mac/ops 握手新鲜、ops conf 与 E2E 前语义等价、
hub ping 13.8ms 与基线一致），临时面板与全部现场文件已清除。

实测暴露并修复的三个问题（切换期间使用端零中断得以验证的前提）：

1. **hub 侧 AllowedIPs 必须为主机路由 /32**：初版按子网位渲染成 x.x.x.x/24，成员间
   allowed-ips 在内核 trie 中互相覆盖，运行态仅最后一个 peer 持有网段。现役 wg1 的真实
   conf 亦为 /32 形态，已对齐（applyHubNode / rebuildHubConf 两处）。
2. **巡检成员状态只认现役 hub**：备胎 dump 是陈旧镜像（成员不向备胎握手），参与判定会把
   全网误标离线、流量回退为备胎旧计数。patrolHub 增加 active 门控，备胎仅做健康检查与
   流量基线。
3. **预检对「已在网成员」的重复配置降级**：校正备胎/重下发本就是在有接口的节点上执行，
   WGAlloc.Reprovision（hub 槽位或成员已存在时自动置位）将同名接口由阻断降为警告
   （原配置仍自动备份）；外来网络的同口冲突依旧阻断。

E2E 过程注记：切换执行中 ops 的 WG 路径随 canary 翻转而断，切回依赖预置于 ops 本地的
看门狗（127.0.0.1 直连面板 API）——生产上等价路径为「切换完成后在组网页面按提示切换设备
凭证」，面板本体不经 WG 亦可管理两端公网 SSH。
