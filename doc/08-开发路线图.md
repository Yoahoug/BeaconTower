## 目录结构（M1 起建立后端）

Go module 位于仓库根（`main.go` + `internal/`），与 `web/` 平级，单容器结构见 [02 文档第 5 节](./02-总体架构与技术选型.md)。前端已在 `web/` 就位，M1 时把 `npm run build` 产物经 `go:embed` 接入二进制。

## 技术债与预留

- 会话目前用服务端表（可吊销）；如需多管理员/再加 OAuth2 登录，届时评估；
- Argon2id 参数写在哈希串内，日后可平滑升级；
- 温度/GPU 指标：二期按需加进采集模板（仅部分硬件支持）；
- 告警通知：二期，触发窗口设计直接借鉴 Nezha（见下）。

## 附录 · 从 Nezha（nezhahq/nezhahq.github.io 文档站）借鉴的清单

参考项目为 Nezha V2 文档站（Agent + gRPC 架构），本项目为其"SSH 无 Agent"的差异化实现，以下设计直接吸收：

1. **卡片指标全集**：CPU/内存/Swap/磁盘/上下行速率/累计流量/Load1-5-15/TCP+UDP 连接数/进程数/uptime —— 即"服务器卡片"的业界完整预期字段集（本项目 v1 全覆盖，温度/GPU 列为可选扩展）；
2. **公开视图隐私收敛**：每节点"对访客隐藏"开关；IP 默认任何公开位置不展示；公私备注分离；访客只能看短期历史、长期历史需登录（→ 本项目 04/05 文档的对应设计）；
3. **敏感字段不回显**：密码/密钥类字段读取接口永不返回，编辑留空=保留原值（→ 04 文档凭据不回显原则）；
4. **存储分层**：内存实时态 + SQLite 业务数据 + 分粒度历史（Nezha: 内存 + SQLite + 可选 VictoriaMetrics；本项目在 SQLite 内用 原始采样表 + 小时聚合表 等效实现，不引入独立 TSDB）；
5. **登录防爆破**：失败计数递增封禁（Nezha 内置 WAF 思路 → 05 文档登录限速节）；
6. **告警防误报三要素**（二期告警功能直接采用）：duration 采样窗口 + 窗口内 ≥70% 样本越界才触发 + "仅一次/总是"模式；
7. **反向经验**：Nezha 默认 admin/admin 账号是常见安全教训 → 本项目改为"首次访问初始化向导"（可选日志令牌防抢注）；Nezha Agent 的 `disable_command_execute` 能力收敛 → 本项目架构上不提供任何远程命令执行，采集命令内置白名单。

与 Nezha 的差异（不再列举文档，见 02 文档 4.1 对比表）：无 Agent、SSH 轮询采集、单管理员、只读监控定位。
