# 09 · 功耗监控设计

> 参考实现：ops 服务器 `10.66.66.66:/data/appdata/power-monitor`（Flask + RAPL，v3）。
> 本文档把它的功耗算法移植进 BeaconTower 的 SSH 无 Agent 采集体系。
> 前端原型已完成功耗展示（总览页 + 卡片）与管理端功耗能力探测/校准。

## 1. 目标与边界

| 项 | 说明 |
| --- | --- |
| 目标 | 在不安装 Agent 的前提下，给出每台节点（硬件支持时）的实时功率、温度、频率与 kWh/电费统计 |
| 能力探测 | 试连/画像回读时探测节点是否暴露 RAPL 功率计接口，写入 `server_profile.power_rapl` |
| 不可用降级 | AMD CPU、多数 KVM/云主机不暴露 RAPL：卡片显示"功耗不可用 · 未暴露 RAPL 功率计接口"，聚合统计跳过该节点 |
| 隐私 | 功率/kWh 属非敏感指标，默认公开（站点设置可关）；功耗不含任何主机信息 |

## 2. 数据来源与采集方式（SSH 只读）

### 2.1 RAPL 能量计数器

Intel Sandy Bridge 起，CPU 通过 MSRs 暴露 RAPL（Running Average Power Limit）能量计数器，Linux 内核在 `sysfs` 暴露为：

```
/sys/class/powercap/intel-rapl:0/energy_uj            # package 域（整颗 CPU），微焦
/sys/class/powercap/intel-rapl:0:0/energy_uj           # core 域
/sys/class/powercap/intel-rapl:0:1/energy_uj           # uncore 域
/sys/class/powercap/intel-rapl:0:2/energy_uj           # dram 域（部分机型）
/sys/class/powercap/intel-rapl:1/energy_uj             # psys 域（整平台，部分机型）
/sys/class/powercap/intel-rapl:0/max_energy_range_uj   # 量程（处理回绕必需）
```

读权限：内核 5.10+ 一般需要 root 或 `powercap` 组；采集用户加入 `powercap` 组即可（文档写进部署清单），无 sudo。

### 2.2 采集命令模板（内置白名单，单次 exec）

在现有采集命令后追加（仍是同一次 `sh -s` stdin 执行，只读）：

```sh
# 功率：两次采集间读 energy_uj 差值 ÷ 量程处理回绕 ÷ 间隔 = 瓦特
for d in /sys/class/powercap/intel-rapl:*; do
  echo "rapl:${d##*/}=$(cat $d/energy_uj 2>/dev/null)"; 
  echo "raplmax:${d##*/}=$(cat $d/max_energy_range_uj 2>/dev/null)";
done
# 温度：优先 x86_pkg_temp / k10temp / cpu-thermal
for z in /sys/class/thermal/thermal_zone*; do
  echo "tz:$(cat $z/type 2>/dev/null)=$(cat $z/temp 2>/dev/null)";
done
# 平均频率
awk '{s+=$1; n++} END{if(n)print "freq_mhz=" int(s/n/1000)}' /sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq 2>/dev/null
# 电池（存在时）：status 与 power_now（µW），放电时整机真实功耗
for p in /sys/class/power_supply/*; do
  [ "$(cat $p/type 2>/dev/null)" = "Battery" ] || continue
  echo "bat:status=$(cat $p/status 2>/dev/null)"; echo "bat:power_now=$(cat $p/power_now 2>/dev/null)"
done
```

面板侧解析规则与现有协议一致：`key=value` 白名单键、数值校验、超长截断。

### 2.3 电池自动校准（移植 power-monitor v3）

笔记本节点放电时 `power_now` 即整机真实功耗；`整机 = 基础功耗 + CPU + DRAM`，其中基础功耗（待机、主板、盘、风扇）不可直接测：

1. 放电期间持续收集 `(power_now, package+dram)` 样本；
2. 放电结束且样本 ≥30 条时结算 `base = mean(power_now) − mean(package+dram)`；
3. 值域合理（2–40W）才采纳，持久化到节点功耗配置；
4. 平时 `整机功率 = package + base`（放电时直接用 EMA 平滑后的 power_now）。

管理端入口：节点编辑器「功耗校准」区块可查看来源（电池自动校准 / 人工设定 / 默认估算）并手动改写基础功耗。

## 3. 面板侧算法（与 power-monitor 一致）

| 算法 | 实现 |
| --- | --- |
| 回绕处理 | `delta = cur ≥ last ? cur − last : (max − last) + cur`；计数器回绕不再产生 0 或尖峰 |
| 异常值过滤 | 单域功率 > 100W 视为读数噪声，丢弃该次采样、保持上一平滑值 |
| EMA 平滑 | `smooth += 0.35 × (raw − smooth)`，消除 2s 采样抖动 |
| kWh 积分 | 梯形法对功率序列真实积分（`Σ (w₁+w₂)/2 × Δt`），不用"平均 × 24h"估算；间隔异常段（重启）不参与 |
| 采集间隔 | 跟随全局采集间隔（默认 10s）；SSH 轮询模型下精度略低于参考实现的 2s，但 kWh 积分不受影响 |

## 4. 数据模型增量

```sql
-- latest_metric / metric_sample 追加：
ALTER TABLE latest_metric ADD COLUMN power_w    REAL;   -- 整机功率（W）
ALTER TABLE latest_metric ADD COLUMN cpu_w      REAL;   -- package 功率（W）
ALTER TABLE latest_metric ADD COLUMN dram_w     REAL;
ALTER TABLE latest_metric ADD COLUMN temp_c     REAL;
ALTER TABLE latest_metric ADD COLUMN freq_mhz   INTEGER;
ALTER TABLE latest_metric ADD COLUMN power_src  TEXT;   -- ac / battery / unavailable

-- metric_hourly 追加（聚合口径同 power-monitor）：
ALTER TABLE metric_hourly ADD COLUMN power_avg REAL;
ALTER TABLE metric_hourly ADD COLUMN kwh       REAL;   -- 该小时梯形积分

-- server_profile 追加（能力探测结果，试连/每日刷新时回读）：
ALTER TABLE server_profile ADD COLUMN power_rapl   INTEGER DEFAULT 0;
ALTER TABLE server_profile ADD COLUMN power_battery INTEGER DEFAULT 0;
ALTER TABLE server_profile ADD COLUMN base_load_w  REAL;      -- 基础功耗
ALTER TABLE server_profile ADD COLUMN base_load_source TEXT DEFAULT 'default';  -- default/calibration/manual

-- 站点设置追加：show_power_public=1 / show_cost_public=1 / electric_price=0.6
```

## 5. API 增量

### 5.1 公开接口（白名单字段追加）

`GET /api/v1/public/servers` 的 `metrics` 内追加（受站点开关 `show_power_public`/`show_cost_public` 控制）：

```json
"power": { "total_w": 8.2, "cpu_w": 2.6, "dram_w": 0.5, "temp_c": 46.5,
           "freq_mhz": 1700, "power_source": "ac",
           "today_kwh": 0.014, "month_kwh": 6.062,
           "est_cost_month": 3.64 }
```

- RAPL 不可用的节点 `power` 字段输出 `null`（前端渲染"不可用"）；
- `show_cost_public=false` 时省略 `est_cost_month`；电价本身永不公开。

### 5.2 汇总接口

`/public/summary` 追加 `watts`（可测节点求和）、`measured_count`、`month_kwh`、`est_cost_month`。

### 5.3 管理接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| PUT | `/admin/servers/:id/power-calibration` | `{"base_load_w": 5.6}` 手动校准基础功耗（`base_load_source=manual`） |
| GET/PUT | `/admin/settings` | 追加 `show_power_public`、`show_cost_public`、`electric_price` |
| （无新接口） | — | 试连/画像回读自动探测 RAPL 能力；采集轮转自然产出功率流 |

## 7. 部署注意

- 被监控机采集用户需能读 `/sys/class/powercap/**/energy_uj`（加入 `powercap` 组，或内核 ≤5.7 默认可读）；
- 容器化部署 BeaconTower 本身**不需要**特权（区别于参考实现 power-monitor 需 `privileged: true` 直接读本机 RAPL——本项目经 SSH 在目标机上读，天然绕开容器隔离问题）；
- AMD 锐龙部分型号有 `amd_energy` 驱动但路径不同，二期按需适配。
