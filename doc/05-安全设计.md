# 05 · 安全设计

## 1. 信任边界

| 边界 | 威胁 | 控制手段 |
| --- | --- | --- |
| 访客 → 面板 | 信息泄露、刷接口 | 白名单序列化、只读公开 API、全局限速、安全响应头 |
| 访客 → 管理 API | 爆破、越权 | Argon2id、限速+递增封禁、会话+CSRF、初始化一次性 |
| 面板 → 被监控机 | 凭据泄露、中间人 | 凭据静态加密、host key 指纹(TOFU/严格模式)、只读命令、8s 超时 |
| 被监控机 → 面板 | 恶意输出注入 | 采集输出仅按 `key=value` 严格解析（白名单键、长度上限、数值类型校验），不 eval、不拼 SQL（全部参数化查询） |
| 本地 data 目录 | 拖库 | 凭据字段密文存储 + 主密钥独立存放；文档要求目录权限 700 |

## 2. 加密设计

### 2.1 静态加密（SSH 凭据）

- 算法：AES-256-GCM，每字段独立随机 nonce，密文格式 `nonce(12B) || ciphertext || tag(16B)`；
- 主密钥来源（二选一）：
  1. 环境变量 `BEACON_MASTER_KEY`（32 字节 hex，**推荐**，不落盘）；
  2. 未提供时首次启动随机生成写入 `data/master.key`（0600）——保证开箱可用，但**密钥与库同目录，拖库风险更高**，文档明确建议生产用方式 1；
- 加密对象：SSH 密码、私钥、私钥口令。host/port/用户名明文存储（管理端必需），但公开 API 永不返回；
- **`master.key` 与数据库必须分开备份**：只拖走 `beacontower.db` 拿不到任何凭据。

### 2.2 密码哈希

- 管理员密码：**Argon2id**（memory=64MB, iterations=3, parallelism=2；参数存于哈希串内便于日后升级）；
- 会话 token：32 字节随机数，库中只存 SHA-256 哈希，明文只在 Cookie 中。

### 2.3 传输加密

- 端口只监听 HTTP，**由反向代理统一上 HTTPS**（Caddy/Nginx + Let's Encrypt，配置示例见 07 文档）；
- 反代下启用 HSTS、并配置 `trusted_proxies` 后正确取真实来源 IP（防伪造头），直连时忽略任何 `X-Forwarded-For`；
- SSH 通道本身端到端加密，host key 校验防中间人。

## 3. 会话与接口防护

| 项 | 设计 |
| --- | --- |
| 会话有效期 | 24h 滑动过期；登出即吊销（服务端会话表） |
| Cookie | `HttpOnly; SameSite=Strict; Path=/`，HTTPS 环境自动加 `Secure`；域名无关托管可配 |
| CSRF | 双提交 Cookie + `X-CSRF-Token` 头，覆盖所有非 GET 管理 API |
| 登录限速 | 单 IP 5 次/分钟；连续失败触发**递增封禁**（借鉴 Nezha 内置 WAF 思路：封禁时长随失败次数增长：5m → 15m → 1h → 24h） |
| 初始化保护 | 仅未初始化可用；完成后接口永久 403；可选 `BEACON_SETUP_TOKEN` 日志令牌防公网抢注 |
| 密码策略 | ≥10 位，须含大小写字母+数字+符号；改密需验证旧密码 |
| 审计 | 登录/登出/密码修改/节点增删改/设置变更全部记录；来源 IP 仅存 **SHA-256 哈希**（防泄露，保留聚合分析能力） |
| 响应头 | `Content-Security-Policy: default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer` |

## 4. 隐私脱敏（公开面）

1. **公开 API 字段白名单**：序列化结构体不含任何敏感字段，从代码层面杜绝"忘了删"（见 04 文档 1.2）；
2. IP/主机名/端口/用户名/私有备注/失败原因：仅存在于管理端接口；
3. 地区展示由 **IP 自动定位生成**（国家/地区级，城市级默认关闭）：公开接口只输出地理**文案**（如 "香港"），出口 IP 本身不出现在任何公开接口；管理员可覆盖为自定义文案（覆盖后停止自动更新）；
4. 每节点 `hidden` 开关 + 站点级"完全私有模式"（开启后所有公开 API 要求登录，对应 Nezha 的 `force_auth`）；
5. 访客历史曲线分级：短期（≤24h）开放，长期（7d+）默认仅登录可见、可配置；
6. 错误信息不泄露内部细节：SSH 失败原因只在管理端展示；公开页离线只显示"离线"。

## 5. SSH 侧最小化

- 文档建议被监控机使用**专用低权限用户**（免 sudo）跑采集命令，全部命令为只读（`/proc`、`df -kP`、`uname` 等）；
- 公网 IP 定位命令同属白名单：优先在 SSH 会话内执行只读的出口 IP 查询（`curl` 固定参数访问 `ip-api.com` / `ip.sb` 等回显服务，带超时）；被监控机无外网时回退为"面板所连地址解析"（域名→IP，直连 IP 直接采用），内网地址（RFC1918）标记为"内网"不展示地区；
- 面板侧实现**命令白名单**：采集器只能发送内置模板命令，不存在任何用户可输入的"自定义命令执行"入口（对比 Nezha 的 `disable_command_execute`，本项目从架构上就不提供远程命令执行）；
- 私钥支持口令；支持 Ed25519/RSA/ECDSA；
- 指纹核对：管理端展示 `SHA256:...` 指纹，`strict_host_key` 开启后不匹配即拒绝。

## 6. 容器加固

- 运行用户 `nobody`（或专用 UID），非 root；
- 镜像基于 `alpine`（含 ca-certificates、tzdata），无 shell 依赖的运行时；
- compose 建议：`read_only: true` + 仅 `/app/data` 可写卷；
- 资源限制示例：`mem_limit: 256m`。
