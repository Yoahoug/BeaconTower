# 14 · 公网暴露安全评估（HTTPS 上线前加固，v2.4）

> 场景：面板经反向代理 / 内网穿透隧道挂到公网 `https://tower.yoahoug.dev/`。
> 本文是上线前的威胁模型 + 风险清单 + 处置记录 + 部署前后检查清单；
> 与 doc/05（安全设计）互补——05 讲「系统应该长什么样」，本文讲「挂公网前哪里还不够、改了什么、还剩什么」。
>
> 结论不使用「绝对安全」表述：以下是当前威胁模型下的已知风险与残余风险清单。

## 1. 威胁模型

面板挂公网后，**匿名攻击者**可以：

| 能力 | 说明 |
| --- | --- |
| 访问全部公开路由与公开 API | `/api/v1/public/*`、静态前端、`/healthz` |
| 暴力破解管理登录 | `/api/v1/admin/login` 无限重放（有限速/封禁） |
| 爬取与扫描 | 目录爆破、常见路径探测、漏洞扫描器指纹 |
| 构造畸形请求 | 超大 body、慢速连接（Slowloris）、畸形头 |
| 拉取公开镜像与源码 | GHCR 镜像、GitHub 仓库（公开仓库，代码本身不是秘密） |

**管理登录是唯一防线**，因此认证与会话是加固重点。攻击者**拿不到**的：数据目录（SQLite/master.key 在服务器本地）、SSH 凭据（AES-256-GCM 静态加密）、上游平台令牌（同上）。

审查范围（重点「公开可见内容是否含凭据/内网信息」+「公网可达面的可利用性」）：
git 全历史、镜像内容、web/dist 产物、公开 API 字段、认证与会话、反代/隧道、滥用与 DoS、注入与输入面、依赖与供应链。

## 2. 凭据与密钥泄露（最高优先）

### 2.1 git 全历史（80 个 commit，含已删除文件）

| 检查 | 命令 | 结果 |
| --- | --- | --- |
| 凭据类文件名 | `git rev-list --all \| while read c; do git ls-tree -r --name-only $c; done \| grep -iE 'secret\|credential\|\.pem\|\.key\|id_rsa\|\.env\|token\|private'` | 仅 `web/src/styles/tokens.css`（误命中 token 词） |
| 密钥模式 | `git grep -iIE '(AKIA…\|ghp_…\|BEGIN …PRIVATE KEY\|xox…)' $(git rev-list --all)` | 79 处命中，**全部**是 `ServerEditorModal.vue` 输入框 placeholder 文本 `-----BEGIN OPENSSH PRIVATE KEY-----`，非真实密钥 |
| 密码赋值 | `git grep -iE 'passw(or)?d\s*[:=]' $(git rev-list --all)` 过滤字段名/文档语义后 | 无硬编码密码 |

**结论：已核实无凭据泄露，无需轮换。** `.env`/`*.key`/`data/` 均在 `.gitignore` + `.dockerignore` 双重排除内。

### 2.2 镜像内容（本地 `docker build` 实测，非纸面推断）

```sh
docker run --rm --entrypoint sh beacontower:sec-audit -c 'ls -laR /app'
```

- `/app` 只有 `beacontower` 二进制（27MB）+ 空 `data/`（volume 挂载点）；
- 无 `.git`、无 `doc/`、无 `web/` 源码、无 `node_modules`、无任何 `*.db`/`*.key`；
- 二进制内 78k 个字符串中唯一 "BEGIN OPENSSH" 是前端表单 placeholder（同 §2.1）；
- 链路保证：`.dockerignore` 排除 `data/ *.db *.key .env .git` → Dockerfile 阶段 3 只 `COPY` 二进制。doc/ 与源码即使进了构建上下文，也不会进运行镜像。

### 2.3 web/dist 产物

| 检查 | 结果 |
| --- | --- |
| sourcemap | `find web/dist -name '*.map'` → 0（vite 默认不产出） |
| 环境数据泄露 | bundle 内 `10.66.66.x`/`192.168.x`/`frp-oil.com`/真实公网 IP → 无 |
| 管理端代码混入公开首屏 | 无——管理端全部路由懒加载（独立 chunk：`ServersView`/`FrpView`/`MeshView` 等），公开页首屏 chunk 不含管理代码（doc/10 §9 回归确认） |
| 前端 bundle 中的内网字符串 | 仅 3 处管理端表单**默认值/占位符**（WG 网段建议 `10.66.66.0/24`、frp `localIp` 默认 `127.0.0.1`、SSH host 示例 `192.168.240.1`），非环境数据，属设计行为，接受 |

### 2.4 文档中的内网拓扑（接受风险）

README 与 doc/09/11/12 含 WG 网段（`10.66.66.0/24`）、hub 公网 IP + UDP 端口、frp 节点域名、SSH 备用通道端口。
处置：**接受并说明理由**——
- WG 端点对未授权包静默丢弃（无握手密钥的 UDP 包不产生任何响应），公网 IP:端口本身不构成可利用面；
- frp 节点域名是平台共享资源（数千用户共用同一批节点）；
- SSH 备用通道指向 frp 隧道，认的是服务器口令，泄露端口不泄露凭据；
- 这些文档对仓库的运维透明度价值大于模糊化的安全收益。
- 若后续希望进一步收敛，可把 doc/11/12 迁到私有位置，属维护者决策。

### 2.5 GHCR 包可见性

镜像只含二进制（见 §2.2），公开无泄露面。**建议保持 public**：私有会让服务器 `docker pull` 需要 PAT，增加凭据管理面而收益趋近于零。

## 3. 公开面信息泄露

逐个走查公开路由响应字段（对照 doc/04 §1 白名单）：

| 路由 | 结论 |
| --- | --- |
| `/public/summary` | 仅计数/速率/功耗聚合值，白名单内 |
| `/public/servers` | 白名单序列化（id/name/region/tags/note_public/status/profile/metrics/power/traffic_today）；IP/主机名/SSH 信息在 SQL 层不查（`SnapshotRows`），`hidden` 节点不入快照 |
| `/public/servers/:id/history` | 字段白名单 `ts/cpu/mem/disk/net/power`；`hidden` → 404；7d 匿名默认 401 |
| `/public/servers/:id/traffic` | 仅按日收发字节；`hidden` → 404 |
| `/public/stream` | 首帧/更新与 `/servers` 同一快照结构 |
| `/public/frp` | 硬白名单 + 回归测试（`frp_public_test.go` 禁止串扫描：账号名/UID/实名/套餐/节点域名/隧道名/端点/内网地址均断言不出现） |
| `/public/wg` | 硬白名单 + 回归测试（`wg_public_test.go`：网段/端点/公钥/错误原文/设备成员名均不下发，成员只给名字+在线布尔） |

**已修复**：`FRPPublicSnapshot` 三个错误分支原先回显 `err.Error()`（SQLite 错误串可能含库文件路径）——改为记服务端日志、对外只回「读取失败」（`internal/handler/frp.go`）。管理端接口的 `err.Error()` 回显保留（仅管理员可见，且上游错误原文是排障必需）。

**错误响应统一化**：公开 API 全部走 `{code,msg,data}` 包装；`/api` 未命中返回 JSON 404（绝不回 HTML）；gin `Recovery()` 兜住 panic（不回堆栈，只 500）。其余公开 handler 的 DB 错误本就返回固定文案，无堆栈/SQL/内部路径回显面。

## 4. 认证与会话

| 项 | 现状 | 结论 |
| --- | --- | --- |
| 密码哈希 | Argon2id m=64MB t=3 p=2（参数内嵌哈希串） | 达标；单次验证 ~100ms，与 5次/分 限速叠加后爆破不可行 |
| 用户名枚举 | 用户名不匹配也跑同代价 DummyHash 验证，错误文案统一 | 达标 |
| 登录限速 | 单 IP 5次/分（`LoginRL`）+ 递增封禁 5m→15m→1h→24h（`LoginBlocker`，带 Sweep 防膨胀、防共享出口 IP 永久锁死） | 达标 |
| 初始化劫持 | `Setup` 先查 `HasAdmin`，已初始化 → `1004`；`CreateAdmin` 唯一约束兜底竞态；可选 `BEACON_SETUP_TOKEN` | **实测确认**：初始化后再 POST /setup 返回 `{"code":1004}`。公网上线前建议在首次启动时设 `BEACON_SETUP_TOKEN`（见 §9 清单） |
| Cookie | `HttpOnly; SameSite=Strict; Path=/`；`Secure` 在 `TLS!=nil 或 X-Forwarded-Proto=https` 时置位 | 达标（§7 反代侧须确保转发 proto 头，否则 cookie 无 Secure） |
| 会话固定 | 登录/初始化成功都 `issueSession` 发**新** token（32B 随机，库存 SHA-256） | 达标（登录即轮换） |
| 登出 | 服务端 `DeleteSession` + 清 cookie | 达标 |
| 改密 | 验旧密码 + 吊销其他会话（当前会话保持） | 达标 |
| 会话有效期 | 24h 滑动（剩余 <1h 才续期） | 达标 |
| CSRF | 双提交 Cookie + `X-CSRF-Token`，覆盖**全部**非 GET 管理 API（`RequireAuth` 组与 `logout` 均挂 `RequireCSRF`） | 达标；SameSite=Strict 为第二层 |
| 审计 | 登录/失败/登出/改密/设置/节点增删全记录，来源 IP 只存 SHA-256 前 16 hex | 达标 |
| **已知限制（已缓解）** | 会话校验无 IO 限速（每请求一次 DB 读）——公开 API 的 IP 限流（§5）使匿名请求无法高频触达管理端校验路径；管理端另有认证前置 | 风险低，接受 |

**建议但需用户拍板（未实现）**：
1. **管理端 TOTP 二次验证**——面板已上公网，TOTP 是防口令泄露/弱口令的最后闸门。实现量中等（TOSI 库 + 绑定流程 + 前端表单），建议下一版本立项；
2. `BEACON_SETUP_TOKEN` 的值轮换（如曾打印在日志里）；
3. 管理端可考虑叠加反代层 basic auth 或 IP 白名单（`/admin` 路径段），把管理面从公网摘除。

## 5. 滥用与 DoS

| 项 | 现状 | 处置 |
| --- | --- | --- |
| HTTP 超时 | 原 `engine.Run`（零超时）→ **已改为显式 `http.Server`**：`ReadHeaderTimeout=10s`（防 Slowloris）、`ReadTimeout=30s`、`IdleTimeout=75s`；**不设 WriteTimeout**（会掐断 SSE 长连） | 已修复 |
| 请求体上限 | 全局 `MaxBytesReader` 1MB（原有） | 保持 |
| 公开路由限速 | **新增** `PublicRateLimiter`：120 次/分/IP 滑动窗口，挂 `/api/v1/public` 全组（`healthz` 除外）。实测 125 连发 → 120×200 + 5×429 | 已修复 |
| SSE 并发 | **新增** `SSEGate(4)`：单 IP 并发 SSE ≤4，超限 429 且名额即时回收（正常断开/panic 双路径 defer 释放）。实测第 5 条并发连接 429 | 已修复 |
| SSE 慢消费者 | 广播对慢订阅 drop 帧（原有，缓冲 4）；**新增** 每次写帧前 `SetWriteDeadline(now+30s)`（经 `ConnContext` 取底层 net.Conn），写端卡死的客户端 30s 后连接被内核终止 | 已修复 |
| history/traffic 刷库 | **新增** 5s TTL 进程内缓存（键 `id|range`，上限 1024 条），SQL 重接口的全局成本被钉死；限速器是每 IP 的，缓存是全局的，两层互补 | 已修复 |
| 响应大小上限 | history 分桶 ≤144 点、7d 聚合 ≤168 行、traffic ≤365 行、servers 快照规模=节点数——响应天然有界 | 设计保证 |

## 6. 注入与输入面

- **SSH 采集**：固定只读脚本常量（`collectScript`），经 stdin 喂 `sh -s`（无引号拼接面）；输出按白名单键 + 长度上限 + 数值校验解析。用户可控字段（节点名/分组/备注）**不进任何 shell**。
- **WG 编排**：接口名过 `sanitizeIface` 白名单（字母数字_-.）；公钥过 `ValidKey`（base64 32B）；conf 注释过 `sanitizeComment`（剥控制字符防 `[Peer]` 段注入）；文件写走 `PushFile`（数据走 stdin，路径过 `ValidatePath`）。试连/画像的 host/port 是管理员输入 → SSH 目标地址，**接受风险**（管理员本可信；错误只打回管理端）。
- **frpc 部署**：容器名/路径由面板生成（`ValidatePath` 校验），配置经 stdin 写入，无用户串拼接进 shell。
- **SQL**：全参数化（store 层无字符串拼 SQL）。
- **静态服务**：`/assets`、`/icons` 走 embed FS（不接受 `..`，无目录穿越/列表）；根级文件（manifest/robots）按**精确文件名**白名单读取（**新增**）。
- **MIME**：**新增**显式注册 `.webmanifest → application/manifest+json` 等表（Go 默认表不认识 `.webmanifest`，会影响 PWA，见 doc/15）。
- **XSS**：前端无 `v-html`/`innerHTML`（grep 确认）；Vue 默认转义；`referrer=no-referrer` 保留。
- **CSP**：`default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'`（应用层下发，**已核对**）。`unsafe-inline` 是 Vue 运行时样式注入与 ECharts 内联样式的现实妥协——收紧需要 nonce 体系改造构建链，收益有限（无动态 HTML 注入点），**接受并记录**。`connect-src` 被 `default-src 'self'` 覆盖，SSE 同源可用。

## 7. 反代/隧道（ops 侧，本次未改动服务器）

应用侧已就绪；以下配置**必须**由反代/隧道层落地，否则 §4 的 Secure cookie 与 HSTS 不生效。Caddyfile 要点（经穿透隧道时，把上游换成隧道本地端口）：

```caddy
tower.yoahoug.dev {
    reverse_proxy 127.0.0.1:8091 {
        # SSE：关缓冲、不限读超时（Caddy 默认不缓冲响应体，flush 即达客户端）
        flush_interval -1
        transport http {
            read_timeout 0        # 不掐长连（默认即 0，显式写出防有人加）
        }
    }
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        # Server 头由 Caddy 自身控制；如需隐藏：
        # -Server
    }
    # Caddy 自动 HTTP→HTTPS 跳转 + 自动证书，无需额外配置
}
```

- **真实 IP 链路**：Caddy（或隧道出口）与面板同机时，反代源 IP 是 `127.0.0.1`；面板设 `BEACON_TRUSTED_PROXIES=127.0.0.1/32`（或隧道网段）后从 `X-Real-IP` 取真实来源。Caddy 默认即发 `X-Real-IP`；**不设则所有访客被当成同一 IP，登录限速/封禁与公开限流会误伤全部访客**——这是 ops 清单第一项。
- **Secure cookie**：依赖面板收到 `X-Forwarded-Proto: https`（Caddy 的 reverse_proxy 默认发）。若中间还隔一层穿透平台，须确认该层透传而非吞掉转发头（验证命令见 §10）。
- **SSE 经 frp**：frp 的 TCP 隧道是透明字节流，不缓冲 HTTP；风险点只在反代层（上面的 `flush_interval -1` 已覆盖）。

## 12. 剩余风险（上线后持续关注）

1. **共享出口 IP**：多个访客同一 NAT 后限流共享计数——真实访客在 120/min 内基本无感，但公司网络大批同事同时刷可能触发；表现是 429，无数据风险。
2. **管理面在公网可达**：登录接口本身是公网入口（限速+封禁+Argon2id 三层），但 TOTP/管理面摘除（§11-13/15）未做前，口令强度就是最后防线。
3. **SQLite 拖库面**：服务器被打穿时 data/ 无二轮防护（master.key 同机）——与 doc/05 §2.1 一致，建议 master.key 与备份分离存放（已有文档要求）。
4. **上游平台令牌**：Sakura/ChmlFrp 令牌静态加密存库，面板被攻破即等于平台账号被攻破——TOTP 落地前这是面板最有价值的攻击目标。
